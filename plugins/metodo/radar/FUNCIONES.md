# Mapa de funciones oficiales de Claude Code
Revisado contra la doc oficial el 2026-10-08. Cada fila sale de su página; si la doc cambia, rehacer la fila.

| Función | Qué es | Cuándo conviene | Cuándo no | Doc |
|---|---|---|---|---|
| Mods | Plugins con handlers en JS o TS que corren dentro del proceso de Claude Code para intervenir eventos (tool calls, prompts), rediseñar elementos de la interfaz (paneles, bandas) o agregar comandos propios inmediatos. | Si querés dibujar paneles o botones en la terminal, reescribir o frenar llamadas a herramientas antes de que se ejecuten, o sumar comandos propios que respondan al instante sin gastar un turno. | Si te alcanza con un hook de configuración, un skill o un servidor MCP; en sesiones WSL (no cargan plugins) o si no confiás en el código (corre sin sandbox con todos tus permisos de usuario). | https://code.claude.com/docs/en/plugins/mods/overview.md |
| /goal | Comando que define una condición de éxito para la sesión. Tras cada turno, un modelo rápido evalúa si se cumplió y hace que Claude siga trabajando solo sin que tengas que mandar prompts a cada paso. | Para tareas grandes con un estado final claro y medible (migrar módulos, pasar tests, limpiar listas de issues) donde no querés intervenir manualmente en cada iteración. | Si querés repetir un prompt por intervalos de tiempo (usá /loop), si buscás validaciones deterministas mediante scripts fijos (usá Stop hooks), o si tenés deshabilitados los hooks. | https://code.claude.com/docs/en/goal.md |
| Canales | Servidores MCP empaquetados como plugins que envían eventos externos (Telegram, Discord, iMessage, webhooks) a tu sesión activa en segundo plano, permitiendo respuestas bidireccionales. | Para interactuar con Claude desde el celular mediante puentes de chat, o para que tu sesión local abierta reciba alertas de CI o monitoreo y reaccione sobre tus archivos reales. | Si no tenés la sesión abierta en tu máquina (los mensajes no entran si la cerrás), en proveedores como Bedrock o Google Cloud (no soportados), o si delegás tareas aisladas en la nube. | https://code.claude.com/docs/en/channels.md |
| Rutinas | Automatizaciones en la nube de Anthropic o entornos self-hosted que guardan un prompt, repositorios y conectores MCP, activadas por cron, llamadas a endpoints HTTP o webhooks de GitHub. | Para tareas desatendidas y periódicas (triage de issues, revisión de PRs, chequeos post-deploy) que deben seguir ejecutándose aunque apagues tu computadora. | Si necesitás acceder a archivos o herramientas locales de tu máquina (usá tareas de escritorio), si te autenticás con API keys de consola sin suscripción a claude.ai, o si tu org las bloqueó. | https://code.claude.com/docs/en/routines.md |
| Worktrees | Directorios de trabajo aislados en git con su propia rama (`--worktree`), que comparten historial con el repo principal para que sesiones o subagentes editen copias separadas sin colisiones. | Si querés laburar en varias ramas, bugs o features en paralelo sin pisar los archivos de tu checkout, o si buscás aislar cambios masivos de subagentes en ramas limpias. | Si no usás git (salvo que definas hooks WorktreeCreate o WorktreeRemove), en repositorios donde reconfigurar dependencias tarde demasiado, o para tareas secuenciales simples. | https://code.claude.com/docs/en/worktrees.md |
| Subagentes | Asistentes con contexto propio. Model admite sonnet, opus, haiku, fable, ID completo o inherit (se fija en frontmatter, --agents JSON, parámetro o env). Effort admite low, medium, high, xhigh, max (se fija en frontmatter, --agents o env). | Para delegar subtareas pesadas que generan mucha salida (búsquedas, logs, tests) sin saturar tu conversación principal, o para limitar herramientas y permisos específicos. | En tareas con diálogo continuo, cambios chicos y puntuales, pasos que comparten mucho contexto previo (salvo forks), o cuando la latencia inicial de arranque importa. | https://code.claude.com/docs/en/sub-agents.md |
| Hooks | Scripts shell, pedidos HTTP, herramientas MCP o prompts que corren automáticamente ante eventos del ciclo de vida de Claude Code para darte control determinista sobre las acciones. | Para aplicar reglas fijas del proyecto: formatear archivos con Prettier tras editarlos, bloquear comandos riesgosos, recibir avisos de escritorio o inyectar contexto tras compactar. | Un hook PostToolUse no puede deshacer lo que la herramienta ya hizo, y no sirve para cambiar la interfaz (para eso, Mods). | https://code.claude.com/docs/en/hooks-guide.md |
| Skills | Carpetas con archivos SKILL.md bajo el estándar Agent Skills que suman instrucciones y contexto modular bajo demanda, invocables por vos con /nombre o por Claude según necesidad. | Cuando repetís las mismas instrucciones, guías o checklists en el chat, o para procedimientos extensos que no querés cargar en CLAUDE.md para no consumir tokens en cada turno. | Para reglas globales breves que deban estar activas en cada prompt (usá CLAUDE.md), o si necesitás conectar herramientas a sistemas externos (usá servidores MCP). | https://code.claude.com/docs/en/skills.md |
| Plugins | Directorios con manifiesto plugin.json que empaquetan skills, agentes, hooks, servidores MCP o mods como una unidad instalable desde marketplaces o carpetas locales. | Para compartir configuraciones completas con tu equipo, instalar herramientas de terceros con un solo comando o versionar múltiples extensiones juntas. | Si te alcanza con un skill, hook o servidor MCP individual (funcionan solos sin plugin), o si querés evitar el gasto de contexto que agregan en cada sesión mientras estén activos. | https://code.claude.com/docs/en/plugins/overview.md |
| /loop y tareas programadas en sesión | Habilidad integrada /loop y herramientas cron (CronCreate, CronList, CronDelete) para repetir prompts a intervalos fijos o dinámicos, o programar recordatorios dentro de la sesión. | Para chequear periódicamente un deploy, monitorear un PR o seguir un build largo mientras tenés la sesión abierta, o dejarte recordatorios para más tarde. | Si cerrás la terminal o la sesión (no siguen corriendo), si necesitás tareas persistentes que anden con la compu apagada (usá Rutinas), o luego de los 7 días de vencimiento. | https://code.claude.com/docs/en/scheduled-tasks.md |
| Scheduled tasks de la app de escritorio | Tareas programadas locales en Claude Desktop que inician una sesión automáticamente según un cron o frecuencia fijada, con acceso directo a tus archivos y herramientas locales. | Para revisiones diarias de código, auditorías de dependencias o briefings de la mañana que necesiten correr contra tus repositorios y herramientas de la máquina. | Si apagás la compu o cerrás la app (solo corren si la app está abierta y la máquina despierta), o si necesitás disparadores por API o webhooks de GitHub (usá Rutinas). | https://code.claude.com/docs/en/desktop-scheduled-tasks.md |
| Workflows dinámicos | Scripts JS que orquestan decenas de subagentes en paralelo. Ultracode es un ajuste o keyword para planificar workflows automáticos en tareas sustanciales (según https://code.claude.com/docs/en/workflows.md y https://code.claude.com/docs/en/model-config.md). | Para tareas masivas que exceden una sola charla: barridos de bugs en todo el repo, migraciones de cientos de archivos, o investigación con verificación cruzada entre fuentes. | Para tareas chicas o secuenciales donde alcanza un subagente, si necesitás confirmaciones del usuario en medio de la corrida, o si querés evitar el alto consumo de tokens que implica. | https://code.claude.com/docs/en/workflows.md |
| Sesiones en la nube | Sesiones de Claude Code en máquinas virtuales aisladas en la nube (de Anthropic o self-hosted), accesibles vía web (claude.ai/code), app móvil, Desktop o CLI con --cloud y --teleport. | Para delegar tareas pesadas o asíncronas sin tener la compu prendida, seguir el avance desde el celular, o activar la autocorrección de PRs ante fallas de CI en GitHub. | Si usás API keys de consola o proveedores cloud (Bedrock, Vertex) sin login en claude.ai, o en repositorios que no sean de GitHub donde necesites subir ramas de vuelta. | https://code.claude.com/docs/en/claude-code-on-the-web.md |
| Agentes en paralelo | Marco comparativo de cinco vías para ejecutar tareas simultáneas: subagentes, vista de agentes (claude agents), agent teams, workflows dinámicos y proyectos. | Para elegir la estrategia según quién coordina (Claude, vos o un script), si los agentes deben comunicarse entre sí y si modifican los mismos archivos mediante worktrees. | Si tenés una sola tarea simple y lineal que entra bien en una única conversación, o si querés evitar multiplicar el uso de tokens y tasa de llamadas con sesiones simultáneas. | https://code.claude.com/docs/en/agents.md |
| Configuración de modelo y effort | Ajustes para definir el modelo (alias como sonnet, opus, haiku, fable o IDs), nivel de esfuerzo de razonamiento adaptativo (low a max), contexto de 1M y ventana de auto-compactación. | Para calibrar costo, velocidad y profundidad de razonamiento según la complejidad del problema, o habilitar contexto de 1M tokens para sesiones largas en repos grandes. | la doc no lo dice | https://code.claude.com/docs/en/model-config.md |
